## 1. 발견 — 여섯

### ①🔴 「실측」 5콜차(반례) 1차 원문이 디스크에 **0건**이다

`00b_착수계획_실측.md` 18행에 「실측」 자신이 이렇게 박아 두었다.

```
**반드시 둘.** … ② **1차 원문은 본문째 폴더에 저장**(`kasa.go.kr` 유실 재발 방지).
```

6-G의 G-5는 **1콜 써서 `RGL03050300.jsp`를 열었다(200 · 218,340 B)**고 적고, 그 페이지에서 낱말 8개(전부 0)와 `<title>`을 인용한다.

```
find /home/user/webtest -iname "*RGL03*" -o -iname "*030503*"   → 0건
```

**보관 파일이 없다.** 218,340 B도, 그 8개 0건도, `<title>` 「장내파생결제 제도」도 **디스크로 재현할 수 없다.** 같은 회차에서 「수집」은 4콜분 응답 본문을 **405·411까지 4건 전부** 보관했다.

**그 값이 이미 밖으로 나갔다.** `운영/09_조회표.md` 신규 2행 중 아래 행이 「`RGL03050300.jsp` 200 · 218,340 B」와 「파생이지 주식이 아니다」를 영구 자산으로 등재했고, `00_공정일지.md` §28-1이 같은 값으로 **§27-6 사장 보고를 갱신**했다.

**판단하지 않음** — 실측이 따로 보관했거나, 6번은 보관 대상이 아니라고 읽은 것인지 모른다.

### ②🔴 G-4 「27건 전부가 메뉴 라벨」 — 그 명령이 내는 것은 **26건**이고 그중 1건은 `data-menu-id`가 아니다

6-G의 G-4가 명령어를 병기했다. **그대로 돌렸다.**

```
grep -o -a -P '.{28}결제.{28}' G2_regulation.krx_main.html | wc -l      → 26
grep -o -a -F '결제'            G2_regulation.krx_main.html | wc -l      → 27
```

- **「결제」 총수 27은 일치한다.** 문맥 추출이 26이다 — grep -o가 겹치는 구간을 하나 버린다. **1건은 문맥으로 열어보지 않았다.**
- 26건 중 **`data-menu-id`가 없는 것이 1건** 있다 → `생상품시장본부/청산결제본부/미래사업본부</a`

**「27건 전부가 `<a … data-menu-id="…">` 안의 메뉴 라벨이다. 본문 문장에 들어간 「결제」는 0건」**이 G-4의 문장이다. **센 값은 26건 중 25건이다.**
이 문장은 `운영/09_조회표.md` 새 행에 **「「결제」 27건은 전부 메뉴 라벨이고 본문 문장 안의 「결제」는 0건」**으로 그대로 옮겨졌다.

**판단하지 않음** — 1건 차이가 결론(T+2 문언 0건)을 바꾸는지는 「감찰」이 정하지 않는다.
