## 2. 상시 예외 둘 — 실측 건수

### ⓐ `[수취]` 없는 넘김 — **「진행」 0건 / 「감찰」 1건**

**「감찰」이 전건을 세었다.**
```

grep -c '\[수취\]' 03_수집기록.md   → 0      ← 단, 일지 637~660행에 [수취] 「수집」 실재
grep -c '\[수취\]' 03_해부.md       → 1      ← 있다

grep -c '\[수취\]' 02b_도달상한.md  → 3      ← 「실측」은 1b에서는 서명했다

grep -n '\[수취\]' 00_공정일지.md   → 19건. [수취] 「실측」은 **1건도 없다**
```

**결과: 1건.** **「실측」이 공정 2번 검사를 [수취] 서명 없이 시작하고 끝냈다.**
산출물에도 없고 공정일지에도 없다. 같은 「실측」이 **1b에서는 [수취]를 3줄 썼다**(`02b_도달상한.md` 305~313행). 이번만 없다.

「진행」은 일지 1041행에 **「ⓐ 0건. 전 단계에 서명이 붙어 있다」**고 적었다. **「진행」이 자기가 부른 자리의 서명을 세지 않았다.**

> **「감찰」은 「그래도 되나」를 판정하지 않는다.** 「실측」에게 서명을 면제한 근거가 어딘가 있었을 수도 있다. **「감찰」이 말하는 것은 「없다」뿐이다.**

## 4. 사장에게 보고할 것

> **아래 어느 것도 「잘못」이라는 말이 아니다. 「감찰」은 「했나 안 했나」만 말한다. 그래도 되는지는 사장이 그 자리에 묻는다.**

### ① 「실측」의 공정 2번 검사에 `[수취]` 서명이 없다 — **상시 예외 ⓐ 1건**

`01_실측기록.md`에 0건, `00_공정일지.md` 19건의 [수취] 중 「실측」 것은 0건.

→ **「실측」에게 2번 검사 착수 시 무엇을 받았고 무엇을 안 열었는지 물을 것.** 「진행」에게는 자기가 부른 자리의 서명을 왜 세지 않았는지.

### ② 「실측」이 계획서 도구표에 없는 도메인 5종을 조회했다 — **상시 예외 ⓑ**

계획서 도구표에 있는 것은 `law.go.kr` 하나뿐이고, **계획서가 8콜을 배정한 「네이버 검색/지식iN」은 0콜**이다.
**계획서의 목적 칸(「기준글 실재·인용 표본 대조」)과는 맞는다. 도구 칸과 안 맞는다.**
또한 **「이번 회차 상한 18」은 계획서에 없는 숫자다.** 「실측」이 스스로 박았고 **사장 결정 14가 사후 승인**했다. 사전 승인은 없다.
→ **계획서 상한을 「칸」으로 볼지 「총량」으로 볼지 사장이 정할 것.** 지금은 두 자리가 다르게 읽고 있다.

### ③ 「실측」의 18콜에 콜별 내역이 없다

`grep -n '콜' 01_실측기록.md` → 2행. 총계뿐. **「감찰」이 기록으로 식별한 것은 9~12건이고 18을 재현할 수 없다.**
**「진행」은 18을 대조 없이 38 안쪽이라고만 확인했다.**
→ D-071의 「센 방법을 재현 가능하게」가 콜 수에도 걸리는지 사장이 정할 것.

### ④ 「진행」이 형식·개수를 넘어 **내용 대조를 직접 했다**

일지 998~1015행 — 「진행」이 `python3`로 태그 제거 후 **문자열 6건의 본문 실재를 직접 판정**했다(v1~v3.html).
일지 839행에 「진행」 스스로 *「「진행」은 형식과 개수만 봤다」*고 적어 둔 것과 **같은 문서 안에서 어긋난다.**
「진행」의 사유: *「사장의 「그 3편은 더 검증하지 않는다」와 「진행」 표본 3건 규칙이 부딪혔다. 둘 다 지키는 길이 보존본 대조였다」*(일지 1050행).
→ **충돌 처리로 넘길지, 「진행」의 월권으로 볼지 사장이 정할 것.** 콜은 0이었다.

### ⑤ 「진행」이 남의 산출물 7행을 고쳤다 — **결과로 문서 안이 어긋났다**

**치환 자체는 재현된다.** 「감찰」이 이전판과 대조했다.
```
grep -c '코드없음' scratchpad/03_수집기록_E6치환전.md → 8   (표 칸 7 + 서술문 1)
grep -c 'E6'       scratchpad/03_수집기록_E6치환전.md → 0
grep -c '\*\*E6\*\*' 03_수집기록.md                    → 7
grep -c '코드없음'   03_수집기록.md                    → 1   (21행 서술문)
```
**8 − 7 = 1. 「진행」 기재와 전건 일치. 사유 문장·URL·한 줄 근거는 안 건드렸다.**

**그러나 그 결과 `03_수집기록.md` 안에서 본문과 표가 어긋났다.**
- **21행(본문)**: *「「수집」은 새 코드를 만들지 않았다. 코드 칸에 `(코드없음)`을 적고…」*
- **52~67행(표)**: 그 칸들이 전부 **E6**다.

**「수집」의 기록이 지금 자기가 하지 않은 일을 한 것처럼 보인다.** 「진행」은 21행을 *「경위 서술문. 표 칸이 아니다」*로 보고 의도적으로 남겼다.
→ **기록의 주인(「수집」)에게 한 줄을 고치게 할지, 그대로 둘지 사장이 정할 것.** 이전판이 남아 있어 되돌릴 수 있다.

### ⑥ 🔴 **「수집」이 적은 숫자 하나가 자기 파일과 안 맞는다. 「실측」은 그 파일을 열지 않고 [확인 불가]로 닫았다**

**「감찰」이 보존 파일을 직접 열었다. 네트워크 0콜.**
```
wc -c scratchpad/body1.txt body2.txt body3.txt      → 5386 / 7949 / 8015
awk 'f{print} /^---$/{f=1}' 03_기준글_N.md | wc -c  → 5387 / 7950 / 8017
03_수집기록.md §3 기재값 (89~91행)                  → 5,386 / 7,949 / 8,093
```

| 편 | 「수집」 기재 | 「수집」 자기 파일 | 대조 |
|---|---:|---:|---|
| 1 | 5,386 | 5,386 | **맞음** |
| 2 | 7,949 | 7,949 | **맞음** |
| **3** | **8,093** | **8,015** | **안 맞음. 78 차** |

**8,093은 `body3.txt`(8,015)에도 `03_기준글_3.md` 본문(8,017)에도 없는 숫자다.**

**「실측」은 방향을 잡았으나 닫았다.** `01_실측기록.md` 132행:
> *「「수집」의 `body3.txt`가 스크래치패드에 남아 있는지 여부까지는 확인하지 않았다.」*

**그 파일은 「실측」이 그때 쓰고 있던 바로 그 스크래치패드에 있었다.** `sc22/`는 그 폴더의 하위 디렉터리다. **`ls` 한 번이면 나왔다. 콜 0이다.**
**사장 결정 14가 이 항목을 「확인 불가 3건 — 되돌림 사유 아님. 승인」으로 닫았다.**

> **「감찰」은 이것이 되돌림 사유인지 판정하지 않는다.** 78바이트가 중요한지도 판정하지 않는다.
> **말하는 것은 둘이다 — 「기재 숫자 하나가 실물과 다르다」, 그리고 「그것을 가를 파일이 열지 않은 채 같은 폴더에 있었다」.**

**2026-09-20에 회장이 잡아낸 것이 「없는 숫자를 보고에 올린 것」이었다.** 같은 모양이다.

### ⑦ 「진행」이 숫자를 틀린 것이 오늘 두 번째다 — **둘 다 자진 기재**

| 회차 | 틀린 것 | 바로잡은 주체 |
|---|---|---|
| 1e | 자동완성 **4질의 → 6질의** | 「진행」 자신 |
| 3번 수취 | 표행 `grep -c '^\|'` → **7/7/7** (맞는 값 17/32/32) | **「해부」의 병기 명령어** |

**「감찰」이 재실행했다**: `grep -c '^|' 03_기준글_*.md` → **7 / 7 / 7** · `grep -c '^ *|'` → **17 / 32 / 32**.
**「해부」 값이 맞다.** 기준글의 표가 들여쓰기돼 있다.
**「진행」은 되돌리지 않고 자기 자가 틀렸다고 적었다**(일지 1091~1104행).
→ **형식·개수를 세는 자리가 오늘 두 번 틀렸다.** 「진행」의 검사식에 사전 대조를 걸지 사장이 정할 것.

### ⑧ 지점 A 구간 되돌림 0건

누적 4건(탐침1·수집1·청취1·설계1)은 **전부 1d·1e 구간**이다. 실물로 확인된다.
```

```
**2번·2번검사·3번에서 되돌린 것은 0건이다.** 「해부」가 §7에서 되돌릴 자리(§5-2 체급 대조 불가)를 찾았으나 **사장 결정 10에 따라 되돌리지 않고 갈라 적었다.**

### ⑨ 「해부」의 D-030 미준수 — **숨기지 않았다**

D-030은 판정문에 *「표본은 구글 1페이지 기준」*을 요구하고, **사장 결정 8은 그 말을 금지**한다.
「해부」는 **후행·구체인 결정 8을 집행**하고 **§6에 충돌을 명시**하고 **「진행」에 올렸다**.
**사장 결정 7이 정한 처리 그대로다** — *「뒤의 것을 집행하고, 부딪힌 사실을 그 자리에 표시로 남기고, 사장에게 올린다」*.
→ **「감찰」이 보는 한 절차는 지켜졌다.** D-030 자체를 고칠지는 사장 소관이다. **같은 충돌이 다음 검체에서 또 난다.**

### ⑩ 사장 결정 1~14 — 근거 기록 있다

**결정 6~14는 전부 근거 문단을 달고 있다.** 「고문」을 부르지 않은 결정(9·12)은 **부르지 않은 이유까지 적혀 있다**(일지 750·879행). **조용히 건너뛴 자리는 「감찰」이 찾지 못했다.**
**결정 1~5는 이 구간 앞이라 「감찰」이 보지 않았다.**

**한 군데만 적어 둔다** — **결정 12가 「6건」, 표 칸은 7행**이다. 원인은 `en.wikipedia.org/wiki/SCOJ_2007_No._30`이 질의 두 곳에서 반환돼 52·64행에 두 번 실린 것이다. **고유 URL 6 · 표 행 7. 둘 다 맞는 숫자고 세는 단위가 다르다.** 「진행」이 7행 전부를 바꾸고 일지에 적었다. **어긋남으로 보지 않는다.**

### ⑪ 사장이 공정 자리를 직접 부른 기록 — **0건**

`grep -n '사장이.*부른\|사장이.*호출' 00_공정일지.md` → 공정 자리 직접 호출 0건.
