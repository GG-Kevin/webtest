### ❌ 재현 안 됨 — **§2의 결론 문장이 화면에 없다**

「탐침」 §2 원문: *"같은 화면 주간값: 9/6~12주 3, 9/13~19주 8, **9/20~26주 15**(진행 중). 같은 주 `추석 휴장`은 **17**이다. → **추석은 D-2인데 개천절 대체공휴일이 D-11에 이미 동급이다.**"*

**내 조회 2회 모두:**

| 주간 | 추석 휴장 | **개천절 대체공휴일** | 한글날 대체공휴일 | 대체공휴일 휴장 | 개천절 증시 |
|---|---|---|---|---|---|
| 2026년 9월 6일~12일 | 1 | **3** | 0 | 0 | 0 |
| 2026년 9월 13일~19일 | 8 | **8** | 2 | 0 | 0 |
| **2026년 9월 20일~26일** | **15** | **0** | 0 | 0 | 0 |

- **9/6~12=3 · 9/13~19=8은 재현된다.** 「탐침」이 맞다.
- **9/20~26의 15는 `추석 휴장`의 값이다. `개천절 대체공휴일`은 0이다.** 컬럼 순서는 추정이 아니라 **explore 응답의 `comparisonItem` 배열을 서버가 그대로 되돌려준 것**으로 확인했다(0=추석 휴장, 1=개천절 대체공휴일, …).
- **`추석 휴장`도 17이 아니라 15였다.** 「탐침」 조회(09:23)와 내 조회 사이 몇 시간 동안 **진행 중인 주 버킷이 움직였다.**

> **적을 것은 이것이다.** 「탐침」 본인이 §5에 **"트렌드 최근 3~4일이 전 검색어 0 · 오늘 값으로 쓰면 안 된다"**고 적었다. 그런데 §2의 결론 문장이 **바로 그 오늘 값(진행 중인 주) 위에 서 있다.** 5년 최고 100은 단단하고, **「지금 이미 동급이다」는 단단하지 않다.**
> **이것이 「값 0」인지 「집계 지연」인지는 못 갈랐다.** 조회는 성공했고 값이 0으로 왔다.

### ⓐ-2 교차 확인 — **네이버 자동완성을 열었다 (신규 경로)**

「탐침」의 구글 자동완성 결론이 **다른 엔진에서도 서는지** 봤다. `ac.search.naver.com` · 2026-09-22 오후 KST · 4질의 전건 HTTP 200.

| 질의 | 네이버 슬롯 | 실물 | 구글(탐침)과 비교 |
|---|---|---|---|
| `10월 5일` | 10 | **1순위 `10월 5일 대체휴일`**, 10순위 `10월 5일 대체공휴일` | **같은 방향.** 구글은 1·2순위가 `공휴일`·`대체공휴일` |
| `10월 5일 주식` | **0 (items 빈 배열)** | 아무것도 안 돌려준다 | **같다.** 구글에도 `10월 5일 + 주식/증시`가 없다 |
| `대체공휴일 주식` | 2 | `대체공휴일 주식`·`대체공휴일 주식장` | 구글 `대체공휴일 증시` 5슬롯보다 얇다 |
| `개천절 대체공휴일` | 4 | `근무`·`이유`·`학교` — **증시 결합 0** | 구글도 `개천절 증시` 트렌드 0 |

> **「탐침」 §2-①의 ⓐ와 ⓒ가 두 엔진에서 독립으로 확인됐다.** 「10월 5일 + 공휴일/대체휴일」은 양쪽 최상위에 있고, **「10월 5일 + 주식」은 양쪽 다 없다.**
> **네이버 자동완성의 뒤 숫자는 전부 `"0"`이다. 검색량이 아니라 슬롯 개수만 준다.**

### ⓐ-3 절대 수치 — **여전히 못 잡았다**

키워드플래너·네이버 검색광고·블랙키위는 조회표대로 막혀 있어 **두드리지 않았다.** 네이버 데이터랩은 API 키(로그인 자격)가 필요해 **시도하지 않았다.** **이 보고의 모든 수치는 트렌드 상대값 + 자동완성 슬롯 수다.**

## §새로 연 경로 — 재현 절차

**① 네이버 자동완성 — 열림(신규)**
```
GET https://ac.search.naver.com/nx/ac?q=<URL인코딩>&con=0&frm=nv&ans=2
    &r_format=json&r_enc=UTF-8&r_unicode=0&t_koreng=1&run=2&rev=4&q_enc=UTF-8&st=100
Referer: https://www.naver.com/
```
HTTP 200 JSON. `items[0]`이 슬롯 배열. **뒤에 붙는 숫자는 전부 `"0"` — 검색량이 아니다. 슬롯 개수만 센다.**

**② 네이버 통합검색 HTML — 열림**
```
GET https://search.naver.com/search.naver?where=nexearch&query=<URL인코딩>
```
**첫 콜이 `Recv failure: Connection reset by peer`(000)로 끊기는 일이 잦다. 재시도하면 붙는다 — 3회 내 5질의 전건 200.**
상단 AI-pick 블록 식별: `data-nlog-area="apB_ugC.b.profile"`(블로그) · `apB_ugC.c.profile`(카페).

**③ 네이버 블로그 발행 절대시각 — 열림(신규)**
```
GET https://rss.blog.naver.com/<blogId>.xml   →  <item><pubDate>
```
**본문 og에는 날짜가 없고, `PostView.naver`는 `"9분 전"` 같은 상대표기만 준다. 절대시각은 RSS에서만 나온다.**

**④ DuckDuckGo 한국 — 열림(신규)**
```
POST https://html.duckduckgo.com/html/
body: q=<원문>&kl=kr-kr
```
HTTP 200. 순위는 `class="result__a"` 앵커 순서, 실제 URL은 `uddg=` 파라미터 안에 있다. **티스토리를 색인한다. 구글 대용이 아니라 별개 엔진이다.**
