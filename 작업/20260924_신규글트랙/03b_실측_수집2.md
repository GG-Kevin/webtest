### ④-2. tossbank `dateModified` 재현 — 03_기준글_3.md 비고("실시간 갱신 페이지 추정")가 실제로 재현됨

두 원문을 `diff`한 결과, **차이는 전부 타임스탬프·조회수·트레이싱 ID뿐이고 기사 본문 텍스트는 1글자도 다르지 않다.**

- `<article>` 태그 `get_text()` 추출 본문(4,495자) — raw와 recheck **완전 동일**(`diff` 출력 없음, exit code 0)
- 바뀐 항목: JSON-LD `dateModified`, Next.js `updatedTime`/`dataUpdatedAt`/`dehydratedAt`(epoch ms), `viewCount`, Sentry trace id — 전부 자릿수가 같은 값으로 바뀌어 전체 바이트 수가 우연히 같게 나온 것

| 항목 | raw(R1, 10:51:00 UTC 조회) | recheck(10:57:55 UTC 조회) |
|---|---|---|
| `dateModified` | 2026-09-24T19:48:21+09:00 (=10:48:21 UTC) | 2026-09-24T19:53:45+09:00 (=10:53:45 UTC) |
| `viewCount` | 46,172 | 46,175 |
| `datePublished` | 2025-12-22 (불변) | 2025-12-22 (불변) |

`dateModified`가 **매 조회마다 조회 시각 직전 값으로 갱신**되고(두 조회 간격 ≈6분55초, `dateModified` 간격 ≈5분24초 — 같은 방향·비슷한 크기로 이동), 그 사이 본문 텍스트는 한 글자도 안 바뀌었다. 이는 **편집자가 실제로 내용을 고쳐서 붙는 타임스탬프가 아니라, 페이지가 렌더링될 때마다(또는 일정 주기로) 자동으로 "지금"에 가까운 시각을 `dateModified`에 채워 넣는 구조**라는 뜻이다.

→ `03_기준글_3.md` 비고의 "**dateModified가 조회 시각과 근접 — 실시간 갱신 페이지로 추정**"은 **재현으로 확인됐다.** 다만 실측이 확인한 것은 "그 가설이 관측과 일치한다"는 사실뿐이다. **"그래서 이 글이 매일 자동 생성되는 상용구다"까지는 실측이 판정하지 않는다** — 이 페이지가 실제 편집된 글(연 1회 수동 갱신 + 기술적으로 매 렌더링마다 타임스탬프만 자동 스탬프)인지, 내용 자체가 주기적으로 자동 생성되는지는 본문 텍스트 재현(위 문단)이 "본문은 안 바뀌었다"고 말하고 있으므로, **적어도 이번 6~7분 창에서는 상용구 자동생성이 아니라 "고정 본문 + 자동 타임스탬프" 쪽 증거가 더 강하다.** 최종 판단(이 신선도 신호를 원고에 어떻게 쓸지)은 「해부」·「설계」 소관.

### ④-3. raw curl 파일 저장 위치 — 감찰 지점 A 지적 관련 확인

감찰이 지점 A에서 "WebSearch 응답 원본 파일이 0건"이라고 지적한 것과 같은 계열의 문제가 이번 재착수의 curl 원본에도 있는지 확인했다.

**확인 결과: `raw_kbthink.html`·`raw_tossbank.html` 둘 다 작업 폴더(`/home/user/webtest/작업/20260924_신규글트랙/`)에는 없다. 스크래치패드(`/tmp/claude-0/.../scratchpad/`)에만 있다.**

```
find /home/user/webtest/작업/20260924_신규글트랙 -iname "*raw*"   → 0건(02_탐침_증빙 폴더의 kin_p*.html·ts_raw.json 등은 「탐침」 산출물이지 이번 curl 원본이 아님)
ls /tmp/.../scratchpad/raw_kbthink.html /tmp/.../scratchpad/raw_tossbank.html   → 존재(121,354B·205,323B, 03_수집기록.md §8-1 기록값과 일치)
```

`03_수집기록.md` §2가 이미 같은 패턴을 1편(card-gorilla)에서 자인한 바 있다: "**원문 HTML 보존 위치**: 스크래치패드 … **스크래치패드는 세션 격리, 영속 보장 없음**." §8-1은 kbthink·tossbank 원본의 저장 위치를 아예 명시하지 않았는데, 실측이 확인해 보니 **card-gorilla와 같은 자리(스크래치패드)에 있고, 작업 폴더 쪽 사본은 없다.** 페르소나 규정(선례 참조 문구)이 이미 경고한 상태 그대로다 — 이번 세션에서는 재조회로 MD5까지 대조돼 문제가 드러나지 않았지만(kbthink 완전 일치), **세션이 끝나거나 스크래치패드가 청소되면 이 두 원본 HTML은 증빙으로 남지 않는다.** 「검증」이 원고 단계에서 다시 열어야 할 때 못 열 가능성이 있다는 뜻 — 이것은 사실 확인이지 실측의 판정이 아니다. 조치(작업 폴더로 옮길지, 운영규칙에 저장 위치를 못박을지)는 사장·「진행」 소관.
