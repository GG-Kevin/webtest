## 왜 이 형태인가

「포착」 문구(06_썸네일문구_18.md)에 나온 표현만 썼다 — 확정 제목·확정

- **배경 재배정**: 「진행」 최초 배정값 RGB(48,32,18)은 같은 배치에서 이미
  완료된 `/12`(54,28,16 다크 버넌엄버)·`/16`(52,40,14 다크 초콜릿골드)과
  채널차 최대 6~8에 불과해 검사3 기준(≥30)에 크게 미달했다. **정방형 외
  전부 자율**(회장 2026-09-23 지시)에 따라 「지면」이 그 턴 안에서 직접
  대체 후보를 탐색해 기존 10장 전부와 채널차 최소 46을 확보하는 다크
  웜차콜(78,70,62)로 교체했다. 정렬축(중앙)·주제어 위치(상단) 배정은
  그대로 따랐다.
- **주제어 "연금저축"**: 캔버스 최상단부(킥커 다음), ExtraBold 232pt,
  전체에서 가장 큰 글자(h=210). 회장 공통사항("가장 중요한 게 가장 크고
  잘 보여야지") 직결.
- **퍼센트 링(도형)**: 본문 65행 실측 세율 16.5%를 단일 원형 게이지로
  강조. 시점별 계열이 없는 단일 값이라 오르내리는 그래프 대신 이 형태를

  무엇을 가리키는지 설명.

- **중앙 정렬**: 킥커·주제어·링·캡션·헤드라인 전부 캔버스 중심축(CX=540)

### 검사 3 재검 — 하드코딩 제거, 디스크 라이브 전건 대조 (2026-09-24, 「지면」 재검)

위 최초 계산은 `existing={'/12':(54,28,16), '/16':(52,40,14), ...}` 식으로
5장을 하드코딩한 값이었다. **디스크의 실제 `/12.png`를 다시 읽으면
`(8,52,72)`로, 하드코딩값 `(54,28,16)`과 전혀 다르다** — 이 배치가 이후
재작업되며 배경이 바뀐 것을 하드코딩이 못 따라간 사례. 「감찰」 지적이
정확했다.

```bash
python3 -c "
import glob
from PIL import Image
files = sorted([f for f in glob.glob('*.png') if f.split('.')[0].isdigit()], key=lambda x: int(x.split('.')[0]))
rgb = {f.split('.')[0]: Image.open(f).convert('RGB').getpixel((5,5)) for f in files}
target = '18'
new = rgb[target]
rows = sorted(((k,v,tuple(abs(a-b) for a,b in zip(new,v))) for k,v in rgb.items() if k!=target), key=lambda r: max(r[2]))
for k,v,d in rows: print(f'/{k} {v} diff={d} max={max(d)}')
mn = min(max(d) for _,_,d in rows)
print('최소:', mn, 'vs /'+[k for k,v,d in rows if max(d)==mn][0])
"
```
