## 1. 면책 페이지 — 초안에서 무엇을 왜 바꿨나

### 1-① 인라인 `style=` 8개를 전부 걷었다 — **바꾼 것 중 가장 큰 것**

```
grep -o 'style=' 폐기/20260922_선행_지면_이전판/면책_페이지_이전판.html | wc -l   → 8
grep -o 'style=' 발행/면책_페이지.html | wc -l                                  → 0
grep -c '<style'  발행/면책_페이지.html                                          → 0
```

**왜** — 사장 지시(2026-09-22) *「발행본 본문에 인라인 `<style>` 블록도 `style=` 속성도 넣지 않는다」*. 초안은 `<div style="line-height:1.8;…">` 래퍼와 `<h2 style="margin:36px 0 12px;font-size:1.3em;font-weight:800;">` 6개를 갖고 있었다.

**걷어도 되는 근거 — 스킨 CSS가 이미 잡는다.** 라이브 스킨(`…/tistory/8996984/skin/style.css`, 81,550B)을 받아 직접 확인했다.

| 태그 | 스킨이 주는 것 | 초안이 `style=`로 주던 것 |
|---|---|---|
| `h2` | `.entry-content h2 {font-size:1.5em}` + `#article-view h2 {margin:1em 0 20px; color:#000; letter-spacing:-1px}` | `font-size:1.3em; margin:36px 0 12px; font-weight:800` |
| `p` | `#article-view p {margin-bottom:30px}` · `.entry-content p {word-break:break-word; line-height:1.625rem}` | `margin:0 0 24px; color:#4a5568` |
| `ul`/`li` | `.entry-content ul {list-style:disc; padding:revert}` · `#article-view ul li {margin:0 0 3px 22px}` | 래퍼 `line-height` |
| `a` | `#article-view a {color:#0070d1; text-decoration:underline}` | 없었음(링크가 없었다) |

**센 명령어**: `curl -sS "https://tistory1.daumcdn.net/tistory/8996984/skin/style.css?_version_=1789966350" -o skin.css` → `HTTP:200 BYTES:81550`, 이후 정규식으로 셀렉터 추출(중간물 `폐기/20260922_선행_지면_중간물/skin.css`).

> **초안의 `<div style="…">` 래퍼는 통째로 지웠다.** 티스토리가 이미 `<div class="entry-content" id="article-view"><div class="contents_style">…` 로 감싼다(라이브 `/pages/개인정보처리방침` 구조를 직접 확인). 래퍼가 하나 더 있을 이유가 없다.

### 1-② 「언제 기준인가」 절을 고쳐 썼다 — **「N월」이 못 박히지 않게**

- **전**: *"각 글 말미에 최종 수정일을 적어 둡니다."*
- **후**: *"각 글은 **작성 시점의 제도와 수치를 기준으로** 씁니다. **기준 시점은 글마다 다르므로**, 각 글 말미의 **최종 수정일**을 보십시오."* (한 문장 추가)

**왜** — 「실측」이 센 라이브 실물이 **두 값**이다: `/5`·`/6`·`/7`은 **8월**, 나머지 15편은 **9월**, 그리고 `/16`·`/17`·`/21`·`/22`는 「월」이 아니라 **「월 일」**로 적혀 있다(`02_선행_실측.md` 166~182행). **한 달을 적으면 다른 편이 틀린 말이 된다.** 착지점은 「몇 월인가」가 아니라 「기준 시점이 있다는 사실」이다.

### 1-③ 실제로 눌리는 내부 링크 2개를 넣었다

| 어디 | 무엇으로 | 응답 |
|---|---|---|
| 「틀린 것을 발견하시면」 | `<a href="/pages/페이지-문의">문의하기</a>` | **HTTP:200** |
| 「광고」 | `<a href="/pages/개인정보처리방침">개인정보처리방침</a>` | **HTTP:200** |

**왜** — 초안은 *"댓글로 알려 주십시오"*로만 끝나 **링크가 0개**였다. §3이 인용한 Essentials *"링크를 크롤링 가능하도록 설정하여 …사이트의 다른 페이지를 찾을 수 있도록"*에 대한 최소한이고, 광고·쿠키는 개인정보처리방침과 실제로 이어지는 내용이다.

### 1-④ 「최종 수정일」 한 줄을 끝에 붙였다

`이 페이지 최종 수정일: 2026년 9월 23일` (KST. 「실측」이 찍은 시각 기준)

**왜** — 나머지 21편이 전부 이 줄을 갖고 있고 §3이 **「남긴다」**로 정한 항목이다. 이 페이지만 없으면 어긋난다.
**위험도 같이 적는다** — `/2`에서 회장이 **죽은 날짜**를 잡은 적이 있다. 그래서 `00_선행_붙이는_법.md` ①에 *「오늘 날짜가 다르면 그 줄만 고치십시오」*를 못 박았다.

### 1-⑤ 「하위 글입니다」 문장은 **넣지 않았다**

§3 원문이 *"필라와의 연결은 없애지 말고 **본문 맥락 안의 문맥 링크**로 바꾼다"*고 정했다. 이것은 **면책이 아니라 글끼리의 연결**이다. 면책 페이지에 옮기면 두 가지가 동시에 틀어진다 — ㉠ 독자가 면책 페이지에서 *"이 글은 …의 하위 글"*을 읽어도 「이 글」이 어느 글인지 알 수 없고, ㉡ 21편 각각에 있어야 할 **문맥 링크가 영영 안 생긴다.** **착지점은 각 글 본문이지 이 페이지가 아니다.**

### 1-⑥ 착지 확인 — 네 문자열

| # | 본문에서 걷을 문자열 | 이 페이지 착지 | 글자 그대로인가 |
|:-:|---|---|---|
| 1 | `본 글을 근거로 한 의사결정의 책임은 이용자 본인에게 있습니다.` | 「책임」 절 | **아니다** — `본 글을` → `이 블로그의 글을`. 한 편의 글이 아니라 사이트 전체를 가리키는 자리라 주어를 바꿨다 |
| 2 | `본 글은 2026년 N월 기준 일반적인 정보 제공을 목적으로 작성되었으며,` | 「무엇을 위한 글인가」(일반적인 정보 제공) + 「언제 기준인가」(기준 시점) 두 절로 쪼갬 | **아니다** — 1-② 사유 |
| 3 | `특정 종목의 매수·매도를 권유하거나 투자 자문을 제공하지 않습니다.` | 「무엇을 위한 글인가」 절 | **그렇다. 글자까지 같다** |
| 4 | `이 글은 동전주 상장폐지 기준 총정리의 하위 글입니다.` | **넣지 않았다** | 1-⑤ 사유 |

`00_선행_붙이는_법.md` 말미에 **「이 페이지의 문장을 본문 21편에 다시 퍼 나르지 마십시오」**를 박았다. D-085 5번의 *「편마다 다르게」*가 걸리는 지점이 여기다 — 면책을 한 장에 모으는 일이 **새 21중복**을 만들면 한 바퀴 돌아 제자리다.

```html
<footer id="footer">

```
**센 방법**: `re.search(r'<footer.*?</footer>', main.html, re.S)` · 길이 **325자**, `post2.html`도 동일 문자열.

### 2-② 삽입 지점 — **문자열로 지정한다** (행번호 아님 · D-071 1-b)

**`skin.html` 에서 아래 문자열을 찾아, 그 줄 바로 다음 줄에 넣는다.**

| | 값 |
|---|---|
| **찾을 문자열** | `<div class="order-menu">` |
| **넣을 것** | `<a href="/pages/안내와-면책">안내와 면책</a>` |
| **건드리지 않는 것** | `<a href="#" class="page-top">TOP</a>` — 그대로 둔다 |

**왜 여기인가** — `.order-menu`는 **지금 비어 있지만(공백 4줄) 스킨이 이미 꾸며 둔 자리**다. 라이브 스킨 CSS에 전용 규칙이 **6개** 있다.

```
#footer .order-menu a           → display:inline-block; margin-bottom:23px; font-size:0.8125em; color:#555
#footer .order-menu a:hover/:focus → color:#333
#footer .order-menu a:before    → 구분점(2×2px)
#footer .order-menu a:first-child::before → content:none
@media(max-width:767px) #footer .order-menu   → margin-bottom:29px
@media(max-width:767px) #footer .order-menu a → display:block; line-height:1.75rem
```

**그래서 CSS를 한 줄도 새로 쓸 필요가 없다.** 인라인 `style=`도 필요 없다. PC는 가로 한 줄, 모바일은 세로 한 줄로 알아서 바뀐다. 첫 자식이므로 앞 구분점도 안 붙는다.

**「지면」이 못 본 것** — `skin.html` 원본은 로그인 벽이라 열지 못했다. 위 문자열은 **라이브 출력에 그대로 남은 것**이고, 티스토리 치환자가 만드는 이름이 아니라 스킨 작성자가 쓴 클래스명이라 `skin.html`에 같은 형태로 있을 것으로 본다. **확정은 아니다.** 그래서 ④ 눈확인 단계를 붙였다.

### 2-③ href — **`/page/…`(단수)가 아니라 `/pages/…`(복수)로 정했다**

「실측」이 *"어느 쪽이 실제로 열리는지 직접 찍어 확인하라"*고 남긴 것을 두드렸다.

```
curl -sS -o /dev/null -w "HTTP:%{http_code} FINAL:%{url_effective}\n" <URL>
```

| URL | 응답 | 리다이렉트 |
|---|---|---|
| `/page/개인정보처리방침` | **200** | **없음** |
| `/pages/개인정보처리방침` | **200** | **없음** |
| `/page/머니프로듀서를-소개합니다` | **200** | 없음 |
| `/pages/머니프로듀서를-소개합니다` | **200** | 없음 |
| `/page/페이지-문의` | **200** | 없음 |
| `/pages/페이지-문의` | **200** | 없음 |

**둘 다 200이고 어느 쪽도 다른 쪽으로 넘기지 않는다.** 그래서 응답 코드로는 못 가른다. **`canonical`로 갈랐다.**

```
curl -sS "https://moneyproducer.co.kr/page/개인정보처리방침" | grep -oE '<link[^>]*rel="canonical"[^>]*>'
→ <link rel="canonical" href="https://moneyproducer.co.kr/pages/%EA%B0%9C%EC%9D%B8%EC%A0%95%EB%B3%B4%EC%B2%98%EB%A6%AC%EB%B0%A9%EC%B9%A8"/>
```

**단수 URL로 들어가도 티스토리 자신이 복수(`/pages/`)를 정본으로 선언한다.** `og:url`도 같고, `sitemap.xml` 3건도 전부 `/pages/…`다. **정본과 다른 주소로 내부 링크를 걸 이유가 없다.**

> **덤으로 잡힌 사실** — 같은 페이지가 두 주소로 200이고 리다이렉트가 없다. 캐노니컬이 있어 색인에는 문제가 없지만, **상단 고정 메뉴 4개가 전부 비정본 `/page/…`를 가리키고 있다.** 「지면」 소관 밖(티스토리가 만드는 메뉴)이고 이번 건도 아니라 **손대지 않았다. 사장에게 넘긴다.**

### 2-④ 발행 전에는 슬러그를 확정할 수 없다

```
curl -sS -o /dev/null -w "HTTP:%{http_code}\n" "https://moneyproducer.co.kr/pages/안내와-면책"  → 404
```

제목 「안내와 면책」에서 만들어질 주소를 `/pages/안내와-면책`으로 **추정**했다(선례: 「머니프로듀서를 소개합니다」 → `/pages/머니프로듀서를-소개합니다`, 공백→하이픈). **추정이지 실측이 아니다.** 그래서 `00_선행_붙이는_법.md` ②를 **주소창 확인 단계로 독립**시켰고, 다르면 그 주소를 ③에 넣으라고 썼다. **여기를 건너뛰면 푸터 링크가 404가 된다 — 이 작업에서 가장 깨지기 쉬운 지점이다.**

## 3. 12번 점검 — 발행 화면 검사 6항목

**방법**: 라이브 `/pages/개인정보처리방침`의 DOM 사슬(`<body id="tt-body-page">` → `<div class="entry-content" id="article-view">` → `<div class="contents_style">`)을 그대로 재현하고, **라이브 스킨 CSS와 content.css를 실제로 내려받아 물려** 크로미움으로 그렸다. 한글은 `자산/폰트/Pretendard-*.otf`를 `fc-cache`로 설치해 썼다.

```
/opt/pw-browsers/chromium-1194/chrome-linux/chrome --headless --disable-gpu --no-sandbox \
  --hide-scrollbars --window-size=1200,2400 --screenshot=render_pc.png file://…/preview.html
```

> **모바일은 iframe으로 쟀다.** 이 컨테이너의 헤드리스는 `--window-size=360`을 줘도 **레이아웃 폭이 360으로 안 내려가고 화면만 잘린다.** 빈 문단 하나짜리 대조 페이지(`ctrl.html`)로 확인했다 — **내용 탓이 아니라 계측기 탓이다.** 그래서 폭 360px `<iframe>` 안에 넣어 다시 그렸다. **이 함정을 적어 둔다.**
