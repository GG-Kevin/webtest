## 09-19 · ③ 수집 착수 불가 — 환경 차단 (사장 기록)

「실측」 호출 직전에 사장이 프록시 상태를 확인했다. **웹 페이지 열람이 전면 차단돼 있다.**

```

  search.naver.com        connect_rejected
  blog.naver.com          connect_rejected

  dart.fss.or.kr          connect_rejected   ← 전자공시

WebSearch(검색 결과 제목·요약)는 작동한다. **본문 열람만 안 된다.**

`/root/.ccr/README.md`: *"403/407은 조직 egress 정책 거부다. 재시도하거나 우회하지 말고 보고하라."* 우회하지 않았다.

| 자리 | 해야 하는 일 | 가능 여부 |
|---|---|---|

## 09-19 · ③ 정지 해제 — 네트워크 재확인 (사장 기록)

### 먼저 — 403의 정체가 바뀌었다

```
> CONNECT kind.krx.co.kr:443 HTTP/1.1
< HTTP/1.1 200 Connection Established        ← 프록시는 통과시켰다
< (HTTP/2) 403  Access Denied                ← KRX 자체 Akamai 엣지
  Reference #18.8e623017... / errors.edgesuite.net

`__agentproxy/status`의 `recentRelayFailures`도 **비어 있다.** 앞선 기록의 `connect_rejected`(조직 egress 정책 거부)와 **다른 종류의 차단**이다. 지금 KRX 403은 거래소가 데이터센터 IP·봇을 막는 것이다.

### 남는 차단 세 곳 — 우회하지 않는다

KRX 403 · 에펨 430은 **사이트 자체의 봇 차단**이다. 헤드리스 브라우저로 뚫는 것은 기술적으로 가능하나 **하지 않는다.** `03_운영규칙.md` §6의 선을 넘지 않는다.

- **KRX** — ⑤ 「검증」 몫이고 ①과 무관하다. 공시는 **DART가 열렸으므로 갈음된다.** 거래정지 현황은 네이버금융으로도 확인된다
- **법령(law.go.kr)** — ⑤ 「검증」 몫. 그때 대체 경로를 다시 잰다
- **에펨코리아** — ① 대상 2건. `01_청취.md` §5 인계표에 원래 없던 출처다. **[실측] 대상에서 빼지 않고 "미확보"로 적게 한다**

### 판단

`01_청취.md` §5가 「실측」에 넘긴 것은 아하18 · 토스9 · 블라인드4 · 액트2 · 금양3 + **네이버 지식iN·카페**다. **KRX는 한 줄도 없다.**
