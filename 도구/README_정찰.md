# 정찰·기록 스크립트 — 사용법 (0토큰, 표준 라이브러리만)

- 만든 곳: 본사(H-189 v3.1 집행, 2026-10-03). 근거: 개편안 v3.1(3군·계산기) · v3 · 본사 안 1-1·1-2·2-1(정찰) · v2 2-2(달력).
- 공통: 네트워크는 환경의 HTTPS_PROXY를 그대로 쓴다. CA는 SSL_CERT_FILE. **TLS 확인을 끄지 않는다.** 403·429·인증서 오류는 「못 열었다(이유)」로 적고 다른 주소·머리글로 우회하지 않는다.
- 비밀값(쿠키·키)은 쓰지 않는다. 남의 글 본문은 받지 않는다(RSS·REST의 제목·날짜·링크만). 원천표에는 제목·URL만 적는다.
- 서치 레포 루트에서 돌린다. 모든 스크립트는 `--repo`를 받고, 없으면 `도구/`의 부모를 레포로 본다.

## 4. 묶기 — 합의 판정 규칙(scout.py)
| 단계 | 규칙 |
|---|---|
| 창 | `--date`가 오늘이면 지금부터 거꾸로 `--hours`(기본 72). 과거 날짜면 그날 23:59 KST가 끝 |
| 분야 거르기 | 제목에 서치 분야 낱말(세금·연금·지원금·정책·증시제도·생활금융 — `FIELD` 표)이 있어야 남는다. 제목에 없으면 카테고리·태그를 보되 카테고리가 주식·코인·ETF면 뺀다 |
| 빼기 | **종목·시황**: 주가·전망·급등·급락·상한가·매수·매도·관련주·수혜주·배당주·코스피·나스닥·비트코인·리딩방 등(`EXCLUDE`), 개별 종목 이름표(삼성전자·테슬라 등 `STOCK_NAMES`)와 회사 이름 꼬리(○○전자·○○바이오·○○증권 등 `STOCK_TAIL`). **개별 상품**: ETF 브랜드(KODEX·TIGER 등)인데 분배금·지급일·세금 문맥이 아닌 것 |
| 공모주 | 공모주·수요예측·균등배정 등은 모두 「공모주 월 일정」으로 모으고 **질문 한 줄**(「M월 공모주 청약 일정」, 사건키 `공모주M월`, 20일 이후면 다음 달)만 낸다. 한 종목 글(수요예측·경쟁률·균등배정)은 세기만 한다(v2 B1 월 1편) |

## 5. 질문 고르기와 질문은행
| 단계 | 규칙 |
|---|---|
| 씨앗 | 닻의 씨앗(예: 「결혼 증여세」·「자녀 증여세」·「가족 간 이체 증여세」) + 「첫 씨앗 + 묶음 제목에 2번 이상 나온 낱말」 1개. `--expand`면 씨앗 × 접미어 9개(어떻게·왜·얼마·언제·신청·조건·계산·기준·2026) |
| 후보 | 씨앗의 **구글 자동완성 원문**(글자 그대로). 점수 = 네이버 자동완성에도 있음 +3 · 묶음 제목 낱말 겹침 ×2 · 질문 낱말(얼마·언제·조건·기준·방법·신청·계산·한도·나이·기간 등) +2 · 3어절 이상 +1 · 기관·사이트 이름으로 끝남 −4 · 같은 낱말 되풀이 −3. 상위 8개 |
| 게이트 먼저 | 후보 8개를 gate_topic에 한 번에 넣는다. **통과 상위 `--max-q`(3)개 + 막힌 것 중 1위 1개**만 원천표·질문은행에 적는다(막힌 줄은 「왜 이 묶음이 막혔나」 기록) |
| 개수 | 고른 질문을 구글·네이버 자동완성에 그대로 다시 넣어 돌아온 개수(0~10). **네이버 원문**은 씨앗 결과나 질문 결과에 글자 그대로(띄어쓰기 무시, 숫자 뒤 프로·퍼센트 = %) 있을 때만 |
| 원문 열림 | 묶음마다 대표 원문 하나(달력 사건이면 달력의 공식 URL, 아니면 닻의 원문 URL)를 `source_open`으로 연다 |
| 게이트 위치 | `<레포>/.claude/gate/gate_topic.py`(서치 사본) → 없으면 `/home/user/claude_ebook/본사/게이트/서치/gate_topic.py` → 둘 다 없으면 「게이트 없음」. `--repo <레포>`로 부른다 |

`운영/질문은행.csv` 칸(고정): 날짜,질문,구글자동완성,네이버자동완성,합의블로그,합의수,원천URL,사건키,사건일,원문URL,열림,gate_topic
| 칸 | 값 |
|---|---|
| 구글자동완성 | 질문을 구글에 넣었을 때 돌아온 개수(0~10). 빈칸 = 못 열었다 |
| 네이버자동완성 | 네이버 원문이면 돌아온 개수, **원문이 아니면 0**(본사 안 1-2 ② 미달) |

| 합의수 | 1군 곳 수 |

## 6. 자동완성 원천(10/3 본사 시험)
| 원천 | 주소 | 돌려주는 것 |
|---|---|---|
| 구글 | `https://suggestqueries.google.com/complete/search?client=firefox&hl=ko&gl=kr&q=<q>` | `[q, [제안 …]]` 최대 10 |
| 네이버 | `https://ac.search.naver.com/nx/ac?q=<q>&con=1&frm=nv&ans=2&r_format=json&r_enc=UTF-8&r_unicode=0&t_koreng=1&run=2&rev=4&q_enc=UTF-8&st=100` | `items[0] = [[제안, "0"], …]` 최대 10 |
- 호출 사이 0.35초(`--sleep`). 같은 회차 안 같은 질의는 한 번만 부른다(캐시). 429가 나면 그 질의는 「못 열었다」로 두고 다시 부르지 않는다.
- 차이(10/3): 구글은 「10%」를 「10 프로」로, 「30대」를 「30 대」로 돌려준다. 맞대기 열쇠는 띄어쓰기를 지우고 숫자 뒤 프로·퍼센트·퍼를 %로 본다. 긴 질의(5어절 이상)는 네이버가 0개를 자주 돌려준다.

## 8. 계산기 쪽(틀.html · calc_check.py) 약속
- calc.py에 `TESTS`(입력 dict 10개, 경계값 포함)와 `compute(**입력) -> dict`를 둔다. 표준 출력에는 표에 실을 숫자를 모두 찍는다.
- 발행.html의 스크립트 안 `function calcCompute(input)`은 compute와 같은 공식·같은 열쇠를 쓰고 `document`를 건드리지 않는다(DOM 연결은 `if (typeof document !== "undefined")` 안에). calc_check가 node로 같은 10개 입력을 돌려 칸마다 맞댄다(차이 0.5 이하 = 같음). node가 없으면 「확인 못 함(node 없음)」.
- 표 숫자 대조: 표 칸의 숫자가 calc 출력 숫자와 표시 자릿수 안에서 같아야 한다(「1,234만」은 만 원 자리까지). 날짜·조문·쪽 번호·단위 없는 한 자리 정수는 세지 않는다. HTML 주석 안은 보지 않는다.
- 수치대장.csv(숫자,단위,원문URL,조항또는쪽,기준일): 원문을 열어 숫자를 글자로 찾는다(쉼표 유무·만·억·천만·「2.4억」·% 표기를 모두 시험). 못 열거나 JS 화면·PDF(pdftotext 없음)면 「확인 못 함」 — 실패로 세지 않고 심사관이 원문과 맞춘다.
- 틀은 표가 기본이다. 스크립트가 티스토리 라이브에서 도는지는 본사가 확인한다(v3.1). 외부 스크립트 0, FAQPage 구조화 데이터 0.
